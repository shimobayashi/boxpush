# BOXPUSH 設計メモ

箱押しパズル BOXPUSH の仕様と、そう決めた理由をまとめる。
面を足したり中身を直したりする人が、最初に読む想定。

決定はすべて「何を決めたか」と「なぜそうしたか」を対にして書く。
理由が無いと後から蒸し返されるし、決定が無いと何に従えばいいか分からないため。
選ばなかった案は最後にまとめて残す。

## 1. どんなゲームか

小さい盤面の箱押しパズルを、1面 15〜60 秒で次々にクリアしていく。
箱を穴に入れた瞬間と面をクリアした瞬間に演出を集中させ、止まらずに進む気持ちよさで引っぱる。

- 全 18 面、固定
- ルールは箱押しパズルそのまま。箱は押すだけで引けない。箱の向こうに壁か別の箱があれば押せない
- 全部の箱が穴に乗ったらクリア

盤面の上限は 7x7、箱は最大 3 個、最短手数は 32 手前後まで。
考えれば誰でも解ける範囲に収め、ヒントも面飛ばしも置かない。
逃げ道を用意しないと決めた以上、そもそも詰まない難易度に抑えるのが筋だから。

## 2. 操作

指を盤面に置いて、そのまま動かした分だけ人が歩く。
1 マス分の距離を動かすごとに 1 歩進み、指を離さずに向きを変えれば続けて進める。

1 スワイプ 1 マスにすると長い移動で何十回も指を離すことになり、
壁まで滑らせる方式にすると箱を押しすぎる事故が起きる。
なぞる方式なら、長い移動も 1 マスの微調整も同じ操作でまかなえる。

盤面の外に、音の入切・戻る・やり直しのボタンを置く。
盤面はなぞる操作専用にして、ボタンと取り合わないようにする。

PC では矢印キーと WASD でも動かせる。
押しっぱなしにすると続けて歩くが、**1 歩を描き切るまで次の 1 歩は受けない。**
キーが繰り返す間隔は OS が決めるので、そのまま受けると目で追えない速さで盤面だけ進み、
箱が穴に入ったのを見る前に穴の先まで押して詰ませてしまう。

箱が穴に入ったときと、壁に当たって進めなかったときは、押し直すまで繰り返しを止める。
最後の箱を吸い込んでいる間とクリア演出の間は、キーも指もいっさい受けない。

## 3. 画面

- 盤面と演出は Canvas 1 枚に描く。画面ごと揺らす演出がやりやすいため
- 面番号・手数・ボタンは HTML 要素で Canvas の上に重ねる。タップ判定や端末の文字サイズ設定をブラウザに任せられるため
- 画像ファイルは持たない。図形と色だけで描く。ライセンスの心配が無く、リポジトリも軽い

暗い背景に光る図形で描く。

| もの | 見た目 |
| --- | --- |
| 背景 | `#0b0f1a` |
| 壁 | 暗い塊 |
| 床 | ほぼ背景と同じ |
| 穴 | 薄い輪 |
| 箱 | 水色に光る角丸の四角 |
| 穴に乗った箱 | 金色 |
| 人 | 白 |

盤面は画面の向きを問わず、ヘッダとテキスト帯を除いた残りに最大で収める。
マスの一辺は `min(使える幅 / 列数, 使える高さ / 行数)` で決め、正方形のまま中央に置く。

盤面の外側は画面の半分以上を占める。ここを真っ暗にしておくと盤面だけが浮いて見えるので、
ゆっくり脈打つ格子を敷いて、やり直さずに続けてクリアしているほど色を濃くする。
残りの箱があと 1 つのときは赤みを差して、張り詰めた見た目にする。

## 4. 演出

ご褒美を出す場所を 2 つに絞る。頻度の高い瞬間と、区切りの瞬間。

**箱が穴に入った瞬間**

- 箱が金色に変わり、光の粒と筋が弾けて、輪が盤面の外へ広がる
- 効果音。1 つの面で入れるごとに音階が上がっていく
- 振動
- 入れた数が増えるほど派手さが積み上がる

**面の最後の 1 個を入れる瞬間**

ここだけ別格にする。山場が無いと波が作れないため。

- あと 1 手で入る状態になると予告が出る。箱と穴が光の線で結ばれ、穴が脈打つ
- 押すと箱がゆっくり吸い込まれ、周りが暗く落ちて箱だけが燃える
- 入り切ったところで一拍止めてから、白く飛ばして爆発させる

**面をクリアした瞬間**

- 盤面のマスが中心から波状に光り、紙吹雪が下の両隅から打ち上がって上からも降る
- ファンファーレ
- 手数を数え上げて見せ、1.5 秒で次の面へ。途中で画面を触れば即座に次へ

ボタンを押さないと進まない作りにはしない。手を止める瞬間がテンポを殺すため。

18 面を全部抜けると、合計手数を見せる全クリア画面を出してから面選択に戻る。

狙い・山場の置き方・数字の一覧・触って分かったことは [effects.md](effects.md) にまとめてある。
演出を触るならそちらを先に読む。

**音**

Web Audio で波を作って鳴らす。音源ファイルは 1 つも置かない。
ライセンスを確かめる手間が無く、音階を上げるような変化を数字で書けるため。

ヘッダの音ボタンで音と振動をまとめて止められる。選択は端末に覚えさせる。
ブラウザの制限で、最初に画面を触るまでは音が鳴らない。これはどの作りでも同じ。

振動は iOS Safari が Vibration API に対応していないため、実際に効くのは Android などに限られる。
（https://developer.mozilla.org/en-US/docs/Web/API/Navigator/vibrate）

## 5. 面データ

`levels.txt` に記号で盤面を描いて並べる。1 ファイルに 18 面。

```
; 01 はじめの一歩
; text: 指でなぞって動かす
#####
#@$.#
#####

; 02 曲がる
######
#@$ .#
#  # #
######
```

| 記号 | 意味 |
| --- | --- |
| `#` | 壁 |
| （空白） | 床 |
| `@` | 人 |
| `$` | 箱 |
| `.` | 穴 |
| `*` | 穴の上の箱 |
| `+` | 穴の上の人 |

- 空行で面を区切る
- `;` で始まる行はコメント
- `; text: ` で始まる行だけは特別で、書いた 1 行が盤面の下の帯に出る。無ければ帯ごと出ない

JSON ではなくテキストにしたのは、エディタで盤面を見ながら直せて、差分もそのまま読めるため。
クオートとカンマの分だけ手書きしにくくなる不利を避けた。

テキスト帯は面 01 と各ブロックの頭（07・13・19・25）にだけ入れる。
難易度が落ちる切れ目と言葉が重なり、新しい章に入った感じが出る。

## 6. 難易度の設計

難しさは、押した回数ではなく**箱の絡み合い**で測る。
一本道を 10 回押す面は、回り込みが要る 3 回押しの面より易しいため。

18 面を 6 面ずつ 3 ブロックに分ける。
ブロックの中で難しくし、次のブロックの頭で落とす。谷も山も後ろほど上がる。

| ブロック | 面 | 点数 | 箱 | 盤面 |
| --- | --- | --- | --- | --- |
| 1 | 01-06 | 7 → 38 | 1-2 | 5x5 - 7x7 |
| 2 | 07-12 | 28 → 54 | 2-3 | 6x6 - 8x8 |
| 3 | 13-18 | 40 → 76 | 3-4 | 7x7 - 8x8 |

目標の表は `src/core/targets.ts` が持っている。
生成スクリプトもテストもそこを読むので、数字を変えるならその 1 か所だけ直す。

面は人が目で選ばず、生成スクリプトが目標に合わせて機械的に選ぶ。
seed を固定しているので、誰が走らせても同じ面になる。

点数の中身・なぜその測り方なのか・何を試して外れたか・生成にかかる時間は
[levels.md](levels.md) にまとめてある。面を触るならそちらを先に読む。

## 7. 作りの構成

```
src/
  core/      盤面・移動・手数・あと 1 手で入る判定。画面に触らない
  solver/    solve.ts   最小押し回数と最小手数を返す
             analyze.ts 面の難しさを測る
  ui/        Canvas 描画・入力・演出
scripts/
  gen.mjs      候補の生成と選別
  measure.mjs  levels.txt の各面の難しさを並べる
levels.txt
test/
docs/  design.md（全体）/ levels.md（面と難しさ）/ effects.md（演出）
```

TypeScript + Vite + Vitest で書く。UI ライブラリは入れない。
盤面の座標や向きの取り違えを型で止めたいのと、毎フレーム動く演出に再描画の仕組みが噛み合わないため。

テストで検査すること。

- すべての面が解ける
- 記号の整合（人が 1 人、箱の数と穴の数が合う、外周が壁で閉じている）
- 難しさが目標の近くに収まっている
- ブロックの中で難しくなり、切れ目で易しくなる。谷も山も後ろほど上がる
- 後半の面は箱が絡み合っている
- 足切り条件に引っかかる面が混ざっていない

難しさの並びは、目標の表ではなく出来上がった面そのものを測って確かめる。
守りたいのは「遊ぶ人が感じる並びに逆転が無いこと」なので。

進捗（どこまでクリアしたか）は localStorage に保存する。
面選択では、クリア済み・今ここ・未解放を一目で見せる。

## 8. 公開

GitHub Actions で main に push するたびにテストを回し、ビルドして GitHub Pages に出す。
ビルド成果物をコミットしないので履歴が汚れず、テストが赤なら公開されない。

ホーム画面に追加できるよう `manifest.json` を置く。
Service Worker は入れないので、オフラインでは遊べない。
代わりに、更新したら必ず最新が出る。

## 9. 選ばなかった案

| 案 | なぜやめたか |
| --- | --- |
| 本格的な大きい盤面（1 面 5〜15 分） | 短時間のプレイと演出に噛み合わない |
| 連鎖などの独自ルール | 仕様と面の設計が一気に重くなる |
| ブラウザ内で毎回生成する無限モード | 生成の待ち時間が入り、難易度がばらつく |
| 外部の公開面集を取り込む | 盤面が大きく方針に合わない。ライセンスの確認も要る |
| 十字キー、タップで自動移動 | なぞる操作で長短どちらの移動もまかなえる |
| ヒント、面飛ばし | 難易度を抑えることで代える |
| 最短手数の表示、星評価 | 「最短で抜けなかった」という失敗を作らない |
| タイトル画面 | 開いた瞬間に面 01 を始める |
| Service Worker でのオフライン対応 | 古い版が残る事故の対策が要る割に、得るものが小さい |
| ビルド成果物を docs/ にコミット | 生成物の差分が履歴に混ざる |
