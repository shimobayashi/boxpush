# 面の作り方と難しさの測り方

面は人が手で選ばず、生成スクリプトが目標の難しさに合わせて機械的に選ぶ。
その「目標の難しさ」をどう測るか、なぜその測り方なのか、何を試して外れたかをまとめる。

全体の仕様は [design.md](design.md)、演出は [effects.md](effects.md) にある。

## 1. 難しさの測り方

**作業量と難しさは別物。** 一本道を 10 回押す面は、回り込みが要る 3 回押しの面より易しい。
押した回数を難しさとして扱うと、後半ほど作業が増えるだけの面ができあがる。

測り方は、人が実際に解いた時間との相関を調べた研究に合わせている。
Jarušek & Pelánek "Difficulty Rating of Sokoban Puzzle"（2000 問・785 時間の実測）の順位相関はこうなっている。

| 見ているもの | 順位相関 |
| --- | --- |
| 状態空間の大きさ | **-0.07** |
| 最短手数 | 0.47 |
| 箱の持ち替え回数 | 0.74 |
| 問題の分解 | **0.82** |

（http://sokoban.dk/wp-content/uploads/2016/02/Difficulty-Rating-of-Sokoban-Puzzle.pdf）

**状態空間の広さは、人の感じる難しさとほぼ無関係。** これが一番大事な発見だった。
このゲームには戻る操作があるので、詰んでも取り返しがつくことも理由になる。

今は `src/solver/analyze.ts` で次の 4 つを数え、点数にしている。

| 数えるもの | 中身 |
| --- | --- |
| 押し回数 | 最小押し回数。作業量の目安 |
| 押しの区切り | 同じ箱を同じ向きに押し続ける並びを 1 つと数えた数（box lines） |
| 箱の持ち替え | 押す箱を変えた回数。行ったり来たりが要るほど多い |
| 問題の分解 | 箱を 2 組に分けたとき、組を行き来する回数のいちばん少ない値 |

```
点数 = 押し回数 + 区切り x 1.5 + 持ち替え x 3 + 分解 x 5 + 箱数 x 2
```

重みは研究の相関の強さに合わせ、分解をいちばん重く見ている。

**「問題の分解」が一番効く。** 箱を 2 組に分けて「片方を全部片付けてからもう片方」で解けるなら 0 になる。
A と B を交互に触らざるを得ないほど大きくなる。
研究でも、同じ箱 4 個の面で、分解できるものは中央値 3 分、できないものは 54 分と 18 倍の差が出ていた。

## 2. 試して外れた測り方

同じ回り道を繰り返さないために、外れたものを残す。
どれも「もっともらしいが、遊んだ人の体感と合わなかった」。

| 試したこと | なぜ外れたか |
| --- | --- |
| 最小押し回数 | 作業量であって難しさではない。一本道でも押し回数は伸びる |
| 詰み率（たどり着ける盤面のうち解けないものの割合） | 状態空間の広さの指標。相関はほぼ無い。戻れるので詰みは痛手にならない |
| 最短手順が何通りあるか | 同上。正解が 1 通りでも、見つけやすければ易しい |
| 一手ごとの安全手の割合 | いちばん厳しい面（安全手 39%）が「易しい」と言われた |
| 箱同士が隣り合っている数 | 難しいと言われた面でも 0 のものがあった |
| 素直に押すだけで解けるか | 難しい面も易しい面も、どちらも「解けない」で差がつかなかった |

体感とずれていると分かったときは、**まず遊んだ人に「何が難しかったか」を聞く**。
今回は「箱を動かす順番が決まっていた」という答えから、持ち替えと分解にたどり着いた。
盤面を眺めて推測を重ねても当たらなかった。

## 3. 難易度のカーブ

18 面を 6 面ずつ 3 ブロックに分ける。
ブロックの中で難しくし、次のブロックの頭で落とす。谷も山も後ろほど上がる。

ずっと右肩上がりだと山場という感じが出ず、落差が大きすぎると山場で止まる人が出るため、その間を取った。

| ブロック | 面 | 点数 | 箱 | 盤面 |
| --- | --- | --- | --- | --- |
| 1 | 01-06 | 7 → 38 | 1-2 | 5x5 - 7x7 |
| 2 | 07-12 | 28 → 54 | 2-3 | 6x6 - 8x8 |
| 3 | 13-18 | 40 → 76 | 3-4 | 7x7 - 8x8 |

目標の表は `src/core/targets.ts` が持っている。
生成スクリプトもテストもそこを読むので、数字を変えるならその 1 か所だけ直す。

面ごとに「分解が何以上」「持ち替えが何回以上」も要求する。
点数だけで選ぶと、押し回数が多いだけの面が混ざるため。

**箱 3 個では難しさに限界がある。** 箱 3 個だと分解が 1 か 2 にしかならず、差がつかない。
研究で 18 倍の差が出ていたのも箱 4 個の面だった。そのため終盤の 2 面は箱 4 個にしている。

## 4. 作る手順

1. 外周を壁で囲い、内側にランダムに壁を置く（床がひとつながりになるまでやり直す）
2. 穴を選び、そこに箱が乗った状態から**箱を逆向きに引いて**初期配置を作る。こうすると必ず解ける
3. 引いた回数が目標に届かない候補を捨てる
4. 解答器で押し回数を見て、明らかに外れた候補を捨てる
5. 難しさを測り、目標の点数と仕掛けの条件に合う候補を集める
6. 集まった中から、目標にいちばん近いものを採る

seed を固定しているので、誰が走らせても同じ面になる。

目標どおりの面が出ないときは、縛りを段階的に緩めて作り直す。
1 面でも作れないと全部やり直しになるので、妥協してでも面を埋める。
緩めた場合はログに「分解の縛りを 1 段ゆるめた」と残る。

### 足切り条件

| 外す | なぜ |
| --- | --- |
| 最初から穴に入っている箱がある面 | 始めから 1 個済んでいると拍子抜けする |
| 回転・鏡写しで別の面と重なる面 | 「さっきと同じ面だ」が続くと進んでいる感じが消える |
| 箱を一方向に押すだけで終わる面（面 03 以降） | 押す向きを変えないなら押し回数が多くても考えることが無い |

人も箱も通らないマスが広い面は、外さない。判定に全探索が要って生成が重くなる割に、害が小さいため。
同じ理由で、盤面の余白も削らない。削ると外周の壁まで落ちて盤面が開いてしまう。

## 5. 生成にかかる時間

全 18 面で**約 4 分**。内訳は面によって大きく違い、条件の厳しい面に時間が集中する。

重くなるのは「難しさを測る」ところ。押し単位で盤面をたどるので、箱が増えると一気に膨らむ。

| 盤面 | 1 候補を測る時間 |
| --- | --- |
| 7x7・箱 3 個 | 数 ms |
| 8x8・箱 4 個 | 約 1.2 秒 |

時間が延びたときに効いた手を、効き目の大きい順に挙げる。

1. **詰み枝刈りを入れる。** 箱が角に入ったら以降をたどらない。
   これが無いと 8x8・箱 4 個で 1 候補 1.5 秒かかり、面 1 つに 26 分かかった
2. **重い測定の前の足切りを強くする。** 引いた回数と押し回数から、
   目標の点数に届きえない候補を先に捨てる。届く下限は点数の式から逆算する
3. **箱が多い面は粘らない。** 候補 3 個・試行 2500 回で打ち切り、見つかった分から選ぶ
4. **調べる盤面の数に上限を設ける。** 状態空間の広さは難しさと無関係なので、
   重い候補を切り捨てても作れる面の難しさは落ちない

足切りを書くときは、**目標に応じて変わる式にする。** 固定値で書くと、
簡単な面まで弾いて「面 01 すら作れない」という事態になる。

## 6. まだ合っていないこと

**測った点数と遊んだ人の体感には、まだずれがある。**
押し回数だけで測っていた頃よりは合うようになったが、一致はしていない。

次に手を入れるとしたら、この辺り。

- **どの面がどうずれたかを集める。** 1 面ずつ「思ったより難しい／易しい」を聞けば、
  今の点数との差から何が足りないかを絞り込める
- **研究の「計算モデル」を試す。** 今使っている分解（相関 0.82）の他に、
  人が状態空間をたどる様子を真似る方法（相関 0.76）がある。組み合わせると精度が上がるかもしれない
- **壁の置き方を構造的にする。** 今はランダムに置いている。
  部屋と通路、行き止まり、狭い折り返しといった型を組み合わせれば、仕掛けが生まれやすくなる

## 7. 面を手で足すとき

`levels.txt` に記号で書き足す（書式は [design.md](design.md) の「面データ」）。
足したら `npm test` を通す。解けること、難しさが目標の近くにあることを検査している。

`node scripts/measure.mjs` を走らせると、各面の点数と内訳が並ぶ。
自分で作った面がどのあたりの難しさかを見るのに使う。
